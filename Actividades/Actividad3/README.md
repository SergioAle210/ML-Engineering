# data-prep-pipeline

Reusable scikit-learn data preparation pipeline for a real customer-churn dataset, built as a shareable Python package so teammates can install and run it identically on any machine.

Notebook (`notebooks/pipeline_diagram.ipynb`) is written in Spanish; this README and the code/comments are in English.

## Dataset

[Telco Customer Churn](https://www.kaggle.com/datasets/blastchar/telco-customer-churn) (Kaggle, author: blastchar) — 7,043 telecom customers, 21 columns (demographics, subscribed services, contract/billing info, `Churn` target). `scripts/download_data.py` fetches it from a public IBM mirror with identical content, so no Kaggle account/API token is required to reproduce `data/telco_customer_churn.csv`.

## CRISP-DM: Business & Data Understanding

**Business Understanding.** Goal: flag customers likely to churn so the retention team can act before they cancel. This repo covers the data-preparation slice of that project — a clean, versioned way to turn the raw export into model-ready features.

**Data Understanding.** Known quality issue used to justify the pipeline stages below: `TotalCharges` arrives as text with 11 blank values (customers with `tenure = 0`), so it must be coerced to numeric. See `notebooks/pipeline_diagram.ipynb` for the quality check and full walkthrough (in Spanish).

## Pipeline stages

| Stage | Module | What it does |
|---|---|---|
| Extraction | `data_prep_pipeline.extraction.DataExtractor` | Selects business-relevant columns from the raw source, coerces `TotalCharges` to numeric. |
| Filtering | `data_prep_pipeline.filtering.DataFilter` | Drops duplicate customers (by `customerID`) and rows with implausible values (business rule: tenure 0–100 months); drops the identifier once used. |
| Type handling | `data_prep_pipeline.pipeline.build_preprocessing_pipeline` | `ColumnTransformer`: numeric columns → median impute + scale; categorical columns → most-frequent impute + one-hot encode. |
| Dataset split | `data_prep_pipeline.pipeline.split_dataset` | Stratified train/test split (target encoded Yes/No → 1/0), run after cleaning and before fitting the preprocessing pipeline. |

Extraction and filtering are combined into one `Pipeline` (`build_cleaning_pipeline`) that runs on the full raw dataframe, target column included, so row-dropping stays aligned with the target. The split happens between cleaning and preprocessing; preprocessing is a second `Pipeline` (`build_preprocessing_pipeline`) fit only on `X_train`, to avoid leakage. `build_pipeline()` assembles all three stages into a single object purely for the diagram in the notebook — see `src/data_prep_pipeline/pipeline.py` for the full rationale.

## Project layout

```
pyproject.toml / setup.py   package metadata (installable, shareable)
src/data_prep_pipeline/     the package: extraction.py, filtering.py, pipeline.py
data/telco_customer_churn.csv  raw Kaggle dataset (generated by download_data.py)
scripts/download_data.py    downloads the raw dataset from Kaggle (via public mirror)
scripts/verify_pipeline.py  end-to-end smoke test, meant to be run (and screenshotted) on each machine
notebooks/pipeline_diagram.ipynb  CRISP-DM notes (Spanish) + rendered sklearn pipeline diagram
tests/test_pipeline.py      pytest smoke test
```

## Installing (each teammate, each machine)

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -e .                # or: pip install -e ".[dev,notebook]"
```

`pip install -e .` reads `pyproject.toml` and installs `data_prep_pipeline` in editable mode — that's the "package" being shared with the team; anyone with the repo can run this one command and get an identical environment.

## Running / verifying

```bash
python scripts/download_data.py     # (re)creates data/telco_customer_churn.csv
python scripts/verify_pipeline.py   # runs extraction -> filtering -> split -> preprocessing end to end
pytest                              # tests/test_pipeline.py
```

`verify_pipeline.py` prints `PIPELINE OK` plus hostname/platform/Python version — run it and screenshot the output on each machine as evidence the packaged pipeline runs unmodified across environments.

## Notebook / diagram

```bash
jupyter notebook notebooks/pipeline_diagram.ipynb
```

Opening the notebook shows the interactive sklearn pipeline diagram (`set_config(display="diagram")`) inline. A static copy is also exported to `notebooks/pipeline_diagram.html`, viewable in any browser without a kernel.
